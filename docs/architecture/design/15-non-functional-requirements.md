# 15. 비기능 요구 (design)

- 근거 spec: [유휴 시 워커를 0까지 줄이기](../../spec/2026-09-18-spec-idle-scale-to-zero/2026-09-18-spec-idle-scale-to-zero.md)
- 적용 영역: `WorkerPool`의 축소 루프와 `PoolConfig`. 현재 제한값은 [as-built/15-non-functional-requirements](../as-built/15-non-functional-requirements.md)가 정본이다.

## 목표: 유휴 시 자원을 0으로

현재 하한은 `min_workers`다. 이번 변경은 **유휴가 지속될 때만** 그 하한을 무시하고 idle 워커를 전부 종료한다. 데몬 프로세스와 열린 포트는 유지한다.

| 값 | 기본 | 환경변수(예정) | 의미 |
|---|---|---|---|
| 유휴 축소 기준 시간 | 60.0초 | `CLAUDE_POOL_IDLE_SCALE_TO_ZERO_SEC` | 마지막 요청 종료 이후 이 시간이 지나면 idle 워커를 전부 종료. `0`이면 비활성 |

기존 `idle_timeout_sec`(60초)·`scale_down_interval_sec`(30초)와 `min_workers`는 그대로 둔다. 새 값은 **하한을 낮추는 조건**이고, 기존 두 값은 **초과분을 다루는 조건**이다.

## 판정 규칙

축소 루프가 깨어날 때마다 락 안에서 아래 순서로 본다.

1. 기준 시간이 `0`이면 기존 규칙만 적용한다(초과 idle 중 `idle_timeout_sec` 경과분 종료).
2. 진행 중 작업이 있으면(배포된 워커가 하나라도 있으면) 축소하지 않는다. `/generate`와 `/jobs`가 같은 `runner.execute`를 쓰므로 실행 중 job도 이 조건에 포함된다.
3. 마지막 요청 종료 이후 경과가 기준 시간을 넘었으면 idle 워커를 전부 종료한다.
4. 그 밖에는 기존 규칙을 적용한다.

- **마지막 요청 종료 시각**은 워커가 풀로 반납되는 시점(`release`)에 갱신한다. 요청 시작이 아니라 종료를 기준으로 삼아야, 긴 요청이 도는 동안 유휴로 오판하지 않는다.
- 초기값은 풀 기동 시각으로 둔다. 기동 후 아무 요청도 없으면 기준 시간 뒤에 예열분이 정리된다.
- 종료 대상은 **idle 워커뿐**이다. 배포된 워커는 건드리지 않으므로 진행 중 요청이 끊기지 않는다.
- 판정과 획득이 같은 조건 변수 아래에서 이뤄져야 한다. 축소가 idle 목록을 비우는 사이에 획득이 그 목록을 보지 않도록 한다.

## 복구

- 워커가 0인 상태에서 요청이 오면 기존 획득 경로가 온디맨드로 스폰한다(`_acquire`의 증가 예약).
- 처리 후 `release`가 `min_workers`까지 보충한다. 즉 요청 하나가 들어오면 예열이 되살아나고, 다시 유휴가 기준을 넘으면 0으로 간다.

## 관측

새 `/health` 필드를 두지 않는다. 축소 여부는 기존 값으로 읽는다.

| 상태 | `/health`에서 보이는 모습 |
|---|---|
| 예열 유지 | `idle = min_workers`, `total = min_workers`, `healthy: true` |
| 유휴 축소 후 | `idle = 0`, `total = 0`, `healthy: true`(빈 풀에서 참) |
| 처리 중 | `busy > 0` |

## 성능·비용 근거

- idle 워커 1개당 메모리 약 236MB(Working Set) / 380MB(Private), 대기 중 CPU 코어 약 2.5% — `~/.claude/rules/common/local-llm-gateway.md`에 기록된 실측값이며 이번 변경에서 재측정하지 않았다.
- 대가: 60초 넘게 쉰 뒤의 첫 요청은 CLI 부팅 비용(약 1초)을 낸다. 같은 파일에 기록된 값이다.

## 미확정 사항

- 잦은 간헐 호출(예: 90초 간격)에서 스폰 빈도가 늘어나는 정도는 측정하지 않았다. 필요하면 기준 시간을 늘려 대응하며, 이번 범위에서 자동 조정은 하지 않는다.
